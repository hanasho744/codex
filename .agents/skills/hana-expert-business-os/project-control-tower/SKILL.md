# Project Control Tower — Expert Standard

## Use for
Inquiry intake, project setup, daily/weekly control, status reviews, task routing, waiting items, ownership, blockers, cross-project prioritization, and postmortems.

## Core rule
A project status is a state of the business process, not a list of messages or completed micro-tasks.

## Project master fields
Project ID/name; client/legal entity; contact/channel; business line; product/service; market; commercial value/budget; expected revenue model; current stage; status; owner; counterpart; next milestone; next action; waiting-for; deadline; decision gate; blockers; risk level; source links; Drive/Notion/communication links; last update; close criteria.

## Status taxonomy
NEW → QUALIFYING → RESEARCH → PROPOSAL/QUOTATION → NEGOTIATION → CONFIRMED → EXECUTING → WAITING → DELIVERY/ACCEPTANCE → CLOSED / ARCHIVED.
Use BLOCKED as a condition, not as a substitute for stage.

## Inquiry intake
Extract and assess:
- who is asking and decision-maker relationship
- explicit need and underlying job-to-be-done
- product/service scope
- market/geography
- quantity/budget/timing
- decision criteria
- missing information
- commercial attractiveness
- capability/fit
- major compliance/delivery constraints
- next best action

## Daily control
For each active project identify:
- what changed since last review
- whether user action is actually required
- waiting party and aging
- next irreversible or critical-path decision
- deadline risk
- what can be delegated/automated/deleted

Do not repeatedly surface WAITING items as active work unless a follow-up trigger is reached.

## Priority model
Prioritize by a combination of:
1. deadline/critical-path urgency
2. expected commercial value
3. probability of conversion/success
4. strategic value/reusability
5. blocker leverage
6. cost of delay
7. required founder-only judgment

## Postmortem
Reconstruct: trigger → information gathering → decisions → communications → execution → waiting → exception/rework → result.
Then classify improvement into: delete / standardize / delegate / automate / retain founder judgment.

## Output
Top decisions → Top 3 actions → timeline by daypart if requested → project status cards → waiting/watch list → blockers → delegated work → learning/SOP updates.
