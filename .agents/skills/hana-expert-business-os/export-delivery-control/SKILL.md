# Export Delivery Control — Expert Standard

## Use for
Production-to-delivery control, inspections, booking, warehouse-in, customs, forwarder communication, B/L, sailing schedule, air/sea shipment, DG handling, import/delivery, and incident reconstruction.

## Core rule
Manage delivery by milestone + evidence + owner + dependency, not by narrative chat history.

## Standard milestone chain
Commercial release → production plan → material readiness → pilot/golden sample → mass production → QC/inspection → packing → booking → export docs → customs declaration → warehouse/gate-in → SI/VGM/DG docs where applicable → B/L/AWB confirmation → ETD → transshipment → ETA → import clearance → final delivery → POD/closure.

## Each milestone must track
- planned date/time
- actual date/time
- owner / responsible party
- prerequisite
- source/evidence
- status
- deviation
- commercial impact
- next action

## Responsibility matrix
Map seller/buyer/factory/trading company/forwarder/broker/carrier/warehouse/importer responsibilities against the actual Incoterm. Distinguish contractual Incoterm from ad-hoc operational assistance.

## Evidence pack
Where applicable retain and reconcile:
PO/contract, invoice, packing list, booking, HS/classification basis, export declaration, warehouse receipt, inspection evidence, product/packing photos, DG documents, SI/VGM, draft/final B/L or AWB, sailing evidence, customs release, delivery receipt, exception correspondence.

## Exception management
For every issue document:
1. expected state
2. actual state
3. root cause / known facts
4. unknowns
5. immediate containment
6. schedule/cost/customer impact
7. owner and deadline
8. recovery route
9. prevention for next shipment
Avoid blame unless evidence requires responsibility allocation.

## Schedule analysis
Use both planned and actual timeline. Quantify delay by milestone and identify true critical-path delay rather than repeating the latest ETA.

## B/L and document control
Check shipper/consignee/notify party, description, marks/numbers, packages, weight/measurement, ports, vessel/voyage, freight term, original/telex release status and amendment cutoff when applicable. Reconcile with invoice/packing/customs information.

## Client update style
Status → what changed → impact → what is confirmed/not confirmed → current recovery action → next confirmation timing. Neutral and evidence-based.

## Closure
Shipment is not closed at ETD. Close only after delivery/POD plus document archive, cost reconciliation, incident lessons, and reusable SOP update where relevant.
